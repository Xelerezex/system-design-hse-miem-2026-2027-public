# ДЗ №1 — Soldout V2

**Трек A · Lite · `lesson-5` · Динамическое ценообразование**

Цена билета увеличивается на **10% после каждых 100 оплаченных мест** в секторе. Стоимость фиксируется при создании бронирования (`hold`) и не меняется при оформлении и оплате заказа.

```text
Catalog: sector_prices
          |
          v
Queue -> Hold (фиксированная цена) -> Order (сумма) -> Pay -> Ticket
          |                              |
          +----- блокировка сектора -----+
```

## Реализация

| Компонент | Назначение |
|---|---|
| `catalog` | Правила ценообразования по секторам |
| `booking` | Согласованный подсчёт продаж, фиксация цены, сумма заказа |
| PostgreSQL | Миграции `0022` (цены), `0023` (индекс), `0024` (счётчик) |
| Инварианты | I7 — сумма заказа; I8 — согласованность счётчика продаж |
| `k6/v2.js` | 30 покупок/с, 60 секунд, распределение 40/20/20/20 по секторам |

## Результаты

Проведено **9 нагрузочных прогонов** (по три для каждой реализации). Во всех прогонах проверки k6 и инварианты прошли успешно.

| Реализация | Медиана Hold p99 | Медиана Pay p99 |
|---|---:|---:|
| Исходная | 5,92 мс | 318,09 мс |
| Частичный индекс | 15,44 мс | 353,70 мс |
| Транзакционный счётчик | 5,75 мс | 318,22 мс |

Индекс ускорил SQL-запрос `COUNT`, но **ухудшил HTTP p99**. Счётчик уменьшил стоимость SQL-операций и дал небольшое улучшение задержки бронирования. Два положительных улучшения HTTP-производительности результатами не подтверждены.
